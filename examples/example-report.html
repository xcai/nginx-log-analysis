四个原始计时

rt：Nginx 接收到客户端首字节至完成请求日志记录的总时间，包含客户端与代理侧的影响。

uct：建立上游连接的时间，HTTPS 时含握手。uht：收到上游响应头的时间。urt：收到上游响应的时间。这三项存在包含关系，不能直接相加。

多次尝试以逗号分隔，内部重定向组以冒号分隔；每项仅在所有 token 均有效时求和。含 -、缺失或非法值的整项记为缺失。

首包等待差值 = UHT − UCT；响应体接收差值 = URT − UHT；请求与上游差值 = RT − URT。仅计算单次上游，2 ms 内的负差归零，超过容差的负差丢弃。它们是近似排查信号，不是精确的应用、数据库或客户端耗时。

聚合与诊断

按方法和原始路径聚合，移除查询参数。路径中的业务标识仍可能敏感；需要时可启用数字 / UUID 路径归一化。

分位数采用 nearest-rank 精确计算。慢请求率以有效 RT 为分母，5xx 错误率以所有有效请求为分母；4xx 单独计数，不视作服务端错误。

诊断阈值：UCT P95 ≥ 50 ms，首包等待差值 P95 ≥ 慢阈值 × 50%，响应体 / 请求阶段差值 P95 ≥ 慢阈值 × 30%。线索需结合状态码、APM、数据库慢查询与 Nginx error log 验证。

累计 RT 是工作量线索，不是 CPU 使用率；并发请求耗时可重叠。分钟桶按请求完成时间计数，不代表并发量。合并输入不会去重。
